# 🎰 BACKEND — как устроена онлайн-игра

Подробное описание серверной части CasinoGame: как запускается стек, как работает
онлайн-мультиплеер, где хранятся деньги и комнаты, как устроены вход по коду,
донаты и админка.

Документ дополняет:
- [`README.md`](README.md) — быстрый старт для игрока/владельца;
- [`ARCHITECTURE.md`](ARCHITECTURE.md) — общая схема проекта;
- [`API.md`](API.md) — справочник HTTP/WebSocket-событий;
- [`DEPLOY.md`](DEPLOY.md) — деплой и эксплуатация.

## 1. Из чего состоит бэкенд

Проект — **два процесса и одна база данных**:

```
┌──────────────────────────────────────────────────────────────┐
│                     ОДИН ЗАПУСК                             │
│  python bot/main.py  (или Docker → /app/start.sh)           │
│                                                              │
│  ┌────────────────────────┐     spawn      ┌───────────────┐ │
│  │  Python: aiogram-бот   │ ─────────────► │ Node.js: сайт │ │
│  │  bot/main.py           │                │ casino/       │ │
│  │  • Telegram polling    │                │ server.js     │ │
│  │  • игры в чате         │                │ • Express API │ │
│  │  • выдача кодов входа  │                │ • Socket.io   │ │
│  │  • донаты/выводы       │                │ • игровой DSP │ │
│  └───────────┬────────────┘                └───────┬───────┘ │
│              │                                     │         │
│              └────────────► SQLite ◄────────────────┘         │
│                       data/casino.db (WAL)                    │
└──────────────────────────────────────────────────────────────┘
```

| Компонент | Файл | Ответственность |
|---|---|---|
| Бот | `bot/main.py` | Telegram-команды, игры в чате, коды входа, супервизор сайта |
| Игровой сервер | `casino/server.js` | HTTP API, Socket.io, правила игр, выплаты, админка |
| База | `data/casino.db` | Пользователи, балансы, операции, статистика, комнаты, сессии |
| Фронтенд | `casino/webapp/` | React SPA, собирается в `casino/webapp/dist` |

Главная идея: **сервер — единственный источник правды**. Клиент присылает только
намерение («бросить кубик», «взять карты»), все проверки, генерация карт,
подсчёт очков, списание и начисление денег выполняются на сервере.

## 2. Запуск всего стека

### 2.1. Локально: `python bot/main.py`

```bash
python bot/main.py
```

Что происходит по шагам (`bot/main.py`):

1. **Поднимается веб-сервер.** `start_web_server()`:
   - проверяет `WEB_AUTOSTART` (по умолчанию `1`);
   - если порт уже отвечает на `/health` — второй сервер не запускается;
   - если нет сборки `casino/webapp/dist/index.html`, запускает
     `npm install` + `npm run build` (один раз);
   - ищет Node.js в `PATH`, стандартных папках и Visual Studio;
   - запускает `node casino/server.js` дочерним процессом и ждёт `/health`
     до 25 секунд;
   - передаёт сайту абсолютный `DB_PATH` — **база у бота и сайта одна**.
2. **Супервизор.** `web_supervisor()` следит за Node-процессом: если сайт упал,
   он перезапускается через 3 секунды.
3. **Проверка конфига.** Без `BOT_TOKEN` бот не стартует, но уже поднятый сайт
   продолжает работать.
4. **Инициализация БД.** `init_db()` создаёт/мигрирует таблицы.
5. **Бот.** Регистрируются роутеры, ставятся команды, включается polling.
6. **Остановка.** `Ctrl+C` / `SIGTERM` → `stop_web_server()` останавливает и
   сайт, и бота (`atexit` + обработчики сигналов).

Поэтому **отдельно `node` запускать не нужно** — сайт живёт как дочерний процесс.

### 2.2. Docker: бот + сайт + база в одном контейнере

```bash
docker compose up --build
```

`Dockerfile` собирает всё необходимое:

| Шаг | Что делает |
|---|---|
| База | `python:3.12-slim`, Node.js 20, `build-essential` для `sqlite3` |
| Python-зависимости | `pip install -r configs/requirements.txt` |
| Node-зависимости | `npm ci --omit=dev` в `casino/` |
| Сборка фронтенда | `npm ci` в `casino/webapp/` → `npm run build` → удаление `node_modules` |
| Исходники | `configs/`, `bot/`, `casino/`, `start.sh` |
| Пользователь | непривилегированный `bot` (uid 1000) |
| Том | `VOLUME ["/app/data"]` — SQLite переживает пересборку |
| Healthcheck | `curl http://localhost:3000/health` каждые 30 с |
| Запуск | `CMD ["/app/start.sh"]` |

`start.sh` выставляет `PYTHONPATH=/app/configs:/app/bot` и делает
`exec python /app/bot/main.py`. Дальше `main.py` сам запускает Node-сервер —
ровно так же, как локально.

`docker-compose.yml` добавляет:

```yaml
env_file: .env          # BOT_TOKEN, ADMIN_IDS, ADMIN_PASSWORD, ...
ports: ["3000:3000"]    # сайт и Socket.io
volumes: [casino_data:/app/data]
restart: unless-stopped # контейнер поднимается после падения/ребута
init: true              # корректная обработка сигналов
```

Проверка после старта:

```bash
curl http://localhost:3000/health
# {"status":"ok","rooms":0,"players":0,"db":"ok"}
```

`amvera.yml` описывает тот же Docker-образ для Amvera Cloud: порт `3000`,
постоянный диск `/app/data`.

> ⚠️ Docker-демон должен быть запущен. Если `docker compose up` падает с
> `cannot connect to the Docker daemon` — это не ошибка проекта, а незапущенный
> Docker Desktop.

## 3. Слои Node-сервера

`casino/server.js` — один файл, но внутри чёткие слои:

```
HTTP (Express)                 WebSocket (Socket.io)
  ├─ /health                     ├─ join / startGame / addBot
  ├─ /api/auth/*                 ├─ playerAction
  ├─ /api/donate*                ├─ rematch / leaveRoom
  ├─ /api/admin/*                └─ disconnect
  ├─ /api/leaderboard, /api/stats
  └─ React SPA (webapp/dist)
                 ▼
        Игровое ядро (Room + правила)
                 ▼
        Деньги: tryDeduct / credit / withTx
                 ▼
        SQLite (WAL)
```

### 3.1. HTTP API

| Группа | Эндпоинты | Назначение |
|---|---|---|
| Служебные | `GET /health`, `GET /api/stats`, `GET /api/rooms` | Мониторинг и публичные комнаты |
| Вход | `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout` | Код из бота → сессия на 30 дней |
| Игрок | `GET /api/leaderboard`, `GET /api/user/:id`, `GET /api/user/:id/stats`, `GET /api/me/transactions` | Топы, статистика, операции |
| Донаты | `GET /api/donate/info`, `POST /api/donate` | Реквизиты и заявка на пополнение |
| Админ | `GET /api/admin/status`, `POST /api/admin/login`, `/overview`, `/users`, `/balance`, `/deposits`, `/withdrawals`, `/transactions`, `/broadcast`, `/settings`, `/close-room` | Полная админка |
| SPA | `GET *` | `webapp/dist/index.html` (React Router) |

### 3.2. Socket.io

Клиент подключается к тому же порту. Основные события:

| Направление | Событие | Данные |
|---|---|---|
| → сервер | `join` | `{ sessionToken, roomId?, gameType, bet, maxPlayers, userName? }` |
| ← клиент | `joined` | `{ roomId, userId, name, isCreator }` |
| ← клиент | `balance` | `{ userId, balance, points }` |
| ← клиент | `roomUpdated` | Персональное состояние комнаты |
| ← клиент | `gameStarted` | `{ gameType }` |
| ← клиент | `gameFinished` | `{ winner, results }` |
| ← клиент | `error` | `{ message }` |
| → сервер | `startGame` / `addBot` / `rematch` | Управление комнатой (создатель) |
| → сервер | `playerAction` | `{ action, cardId? }` |
| → сервер | `leaveRoom` | Выход |

**Важно:** в `join` сервер сначала проверяет `sessionToken`. Если токен валиден,
`userId` берётся из сессии и **игнорирует** присланный клиентом `userId` — нельзя
выдать себя за другого игрока. Без токена разрешён гостевой вход (локальная игра).

## 4. База данных и деньги

### 4.1. Одна SQLite на два процесса

`DB_PATH` по умолчанию `./data/casino.db`. Бот передаёт сайту абсолютный путь,
Docker задаёт `/app/data/casino.db`. Включён `journal_mode=WAL` — параллельное
чтение и запись из Python и Node не блокируют друг друга.

Ключевые таблицы:

| Таблица | Содержимое |
|---|---|
| `users` | Telegram ID (= `id`), имя, `balance` (💰), `points` (⭐) |
| `transactions` | Все движения денег: `deposit`, `withdraw`, `win`, `bet`, `refund`, … |
| `game_stats` | История игр: игра, ставка, результат, сумма, соперник |
| `web_rooms` | JSON-состояние активных веб-комнат |
| `login_codes` | Одноразовые коды входа, `kind = player \| admin` |
| `web_sessions` | Токены игроков (30 дней) |
| `admin_sessions` | Токены админки (12 часов, привязаны к Telegram ID) |
| `deposits` | Заявки на пополнение (`source = site \| bot`) |
| `withdrawals` | Заявки на вывод |
| `settings` | Реквизиты донатов и прочие настройки из админки |

### 4.2. Атомарность

Все денежные операции идут через транзакцию `withTx()`:

```js
await withTx(async () => {
  await dbRun("UPDATE users SET balance = balance + ? WHERE id=?", [payout, userId]);
  await dbRun("INSERT INTO transactions (...) VALUES (...)", [...]);
});
```

Списание ставки (`tryDeduct`) делает `UPDATE ... WHERE balance >= ?` и проверяет
`changes === 1` — нельзя уйти в минус даже при двойном клике.

### 4.3. Где хранятся деньги

Только в SQLite. Клиент получает баланс для отображения, но **не может** его
изменить: любое начисление — это либо выигрыш, рассчитанный сервером, либо
операция админа.

## 5. Вход на сайт по коду

Паролей у игроков нет. Аккаунт — это Telegram ID.

```
Telegram                         SQLite                    Сайт
   │  /site                        │                        │
   ├──────────────────────────────►│ login_codes            │
   │  бот создаёт код (15 мин)     │ kind=player            │
   │  присылает в ЛС               │                        │
   │                               │◄──── POST /api/auth/login {code}
   │                               │      проверка кода      │
   │                               │      used_at = now     │
   │                               │      web_sessions ────►│ token (30 дней)
```

- Код: 8 символов, алфавит без похожих `0/O/1/I`.
- Одноразовый: повторная попытка → `410`.
- Живёт 15 минут, старые коды вычищаются.
- `POST /api/auth/login` возвращает `{ token, user }`; токен кладётся в
  `Authorization: Bearer <token>` и в `sessionToken` при `join`.
- Код админки (`kind=admin`) на странице игрока отклоняется с подсказкой.

## 6. Онлайн-комната: жизненный цикл

### 6.1. Состояния

```
waiting ──startGame──► playing ──финал/ошибка──► finished
   ▲                                              │
   └──────────────── rematch ─────────────────────┘
```

- `waiting` — комната создана, игроки подключаются, ставки ещё не списаны.
- `playing` — ставки списаны, идёт партия, ходы принимает только сервер.
- `finished` — выплаты сделаны, результаты разосланы, комната живёт 15 минут.

### 6.2. Создание и вход

1. Игрок открывает сайт → создаёт комнату: `join` без `roomId`, с `gameType`,
   `bet`, `maxPlayers`.
2. Сервер генерирует код комнаты из 6 символов (`ABC234`), создаёт `Room`,
   добавляет создателя.
3. Другой игрок вводит код → `join` с `roomId`; сервер проверяет, что комната
   существует, не переполнена и ещё не началась.
4. `roomUpdated` рассылается **каждому** сокету отдельно через
   `toJSONFor(viewerId)`: чужие карты и очки скрыты, свои — видны.

### 6.3. Старт и ставки

`startGame` может вызвать только создатель. `startRoom()`:

1. Проверяет минимум 2 игрока.
2. `reserveBets()` списывает ставку с каждого реального игрока.
   Если у кого-то не хватает денег:
   - уже списанные ставки возвращаются;
   - игра не начинается;
   - клиент получает `error`.
3. Инициализирует выбранную игру (`initBlackjack` / `initDurak` / `initDice`).
4. Сохраняет комнату в `web_rooms` и рассылает состояние.

Боты (`🤖 Бот …`) ставку **не платят** и в банк не входят — они существуют только
в памяти комнаты (`BOT_ID_BASE = -9000000000000`), в `users` не пишутся.

### 6.4. Ходы

Клиент отправляет `playerAction`:

```js
socket.emit("playerAction", { action: "hit" });                  // блэкджек
socket.emit("playerAction", { action: "attack", cardId: "A♠" }); // дурак
socket.emit("playerAction", { action: "roll" });                 // кости
```

Сервер:

1. Проверяет, что комната в статусе `playing`, а игрок существует.
2. Передаёт действие в обработчик игры.
3. Обработчик проверяет очередь, наличие карты, правила.
4. Если всё ок — меняет состояние, сохраняет комнату, рассылает `roomUpdated`.
5. Если нет — отправляет `error` **только этому** сокету.

Rate limit: 60 действий за 10 секунд на сокет.

### 6.5. Таймауты и авто-ходы

- `scheduleTurn()` ставит таймер на текущего игрока (`MOVE_TIMEOUT`, по
  умолчанию 30 с).
- Не успел — `autoTurn()` делает безопасный автоматический ход
  (в блэкджеке — `stand`, в дураке — `take`/`pass`, в костях — бросок).
- Для ботов таймер 0.9 с: `botTurn()` играет по простой стратегии
  (набирает до 17, отбивается первой подходящей картой, подкидывает по
  достоинству).
- Таймеры не сериализуются в БД — после рестарта они создаются заново при
  входе игрока в активную комнату.

## 7. Правила игр на сервере

### 7.1. Кости (`dice`)

- Колода 36 карт не нужна.
- Каждый игрок по очереди делает `roll`; значение — `crypto.randomInt(1, 7)`.
- Когда бросили все, `finishDice()` выбирает максимальное значение.
- Победители делят банк; ничья — банк делится поровну.

### 7.2. Блэкджек (`blackjack`)

- Колода 36 карт, тасуется `crypto.randomInt` (Фишер–Йетс).
- Каждому по 2 карты. `blackjackScore()`: туз = 11, при переборе — 10.
- Ходы по очереди: `hit` (взять) или `stand` (хватит).
- При 21+ игрок автоматически останавливается; больше 21 — перебор.
- Когда все закончили, побеждает лучший счёт среди не перебравших.
- Если колода кончилась — создаётся новая.

### 7.3. Дурак (`durak`)

- До 4 игроков, по 6 карт, козырь — верхняя карта оставшейся колоды.
- Первый игрок — атакующий, второй — защищающийся.
- `attack` — положить карту; достоинство должно совпадать с любой картой на
  столе, максимум 6 пар.
- `defend` — отбить карту: старшая той же масти или козырь против не-козыря.
- `take` — защищающийся забирает все карты со стола; атакующий добирает до 6.
- `pass`/`bitto` — атакующий завершает кон, когда все карты отбиты; оба
  добирают до 6.
- Выигрывают все, кто вышел из игры (кончились карты при пустой колоде);
  проигравший — «дурак».

### 7.4. Выплаты

```js
pool       = сумма ставок реальных игроков;
commission = floor(pool * COMMISSION_PERCENT / 100);
prize      = pool - commission;
share      = floor(prize / число_победителей);
```

- Остаток от деления раздаётся первым победителям по +1.
- Каждому реальному игроку пишется `transactions` (`win` / `refund`) и
  `game_stats` (`win` / `lose` / `tie`).
- Боты в выплатах не участвуют.
- Если игра не может начаться или все отключились — `refundRoom()` возвращает
  ставки с типом `refund`.

## 8. Сохранение, перезапуск и очистка

### 8.1. Персистентность

После каждого значимого изменения `saveRoom()` пишет JSON в `web_rooms`:

```sql
INSERT INTO web_rooms (id, state, updated_at) VALUES (?, ?, ?)
ON CONFLICT(id) DO UPDATE SET state=excluded.state, updated_at=excluded.updated_at
```

При старте `loadRooms()` восстанавливает комнаты. Игроки помечаются
`connected=false`, таймеры создаются заново при их возвращении.

### 8.2. Переподключение

Если игрок обновил страницу или пропал интернет:

- сокет отключается, но игрок **не удаляется** из активной игры;
- `player.connected = false`;
- при повторном `join` с тем же `sessionToken` он возвращается в ту же комнату;
- если отключился создатель, права создателя переходят следующему
  подключённому игроку.

### 8.3. Фоновая очистка (раз в минуту)

| Ситуация | Действие |
|---|---|
| `playing`, все люди офлайн > 10 мин | вернуть ставки (`refundRoom`) |
| `finished` > 15 мин | удалить комнату |
| `waiting`, все офлайн > 2 мин | удалить комнату |
| `waiting` > 30 мин | удалить комнату |

Также чистятся старые записи rate limit.

## 9. Донаты

### Через сайт

1. Игрок открывает «💳 Донат».
2. `GET /api/donate/info` отдаёт реквизиты из `settings`/`.env` и последние
   заявки игрока.
3. `POST /api/donate` создаёт `deposits` со `status='pending'`,
   `source='site'`, суммой и комментарием.
4. Админ подтверждает заявку в `/admin` → `POST /api/admin/deposits/:id/resolve`.
5. Сервер в одной транзакции:
   - ставит `status='approved'`, `processed_at`, `admin_id`;
   - начисляет баланс;
   - пишет `transactions` с типом `deposit`.

Отклонение (`approve: false`) баланс не меняет.

### Через бота

Бот пишет в те же таблицы (`source='bot'`), поэтому заявки видны в веб-админке,
а пополнения из админки — в истории игрока.

## 10. Админка: доступ и проверки

Админ-панель — это `/admin` в React-приложении + REST `/api/admin/*`.

### 10.1. Кто может войти

Три условия одновременно:

1. `ADMIN_PANEL_ENABLED` не равен `0` (глобальный выключатель).
2. Пользователь есть в `ADMIN_IDS` (список Telegram ID через запятую).
3. Код выдан ботом именно как админский (`login_codes.kind='admin'`).

Пароль — только запасной вариант:

- `ADMIN_PASSWORD_LOGIN=1` (по умолчанию) **и** `ADMIN_PASSWORD` задан явно;
- `admin123` больше **не** даёт доступ ни через REST, ни через socket.

### 10.2. Как получить код

1. В Telegram: `/admin` → «🌐 Войти в веб-админку (код)».
2. Бот проверяет `ADMIN_IDS`, создаёт код на 15 минут и присылает его.
3. На сайте `/admin` ввести код → `POST /api/admin/login { code }`.
4. Сервер повторно проверяет: код админский, не использован, не истёк, а
   `user_id` всё ещё в `ADMIN_IDS` (если админа убрали — доступ закрыт).
5. Возвращается токен на 12 часов, привязанный к Telegram ID.

### 10.3. Проверка на каждом запросе

`requireAdmin()`:

- токен существует и не истёк;
- если токен привязан к `user_id`, этот ID всё ещё в `ADMIN_IDS`;
- иначе `401` и токен удаляется.

Публичный `GET /api/admin/status` возвращает:

```json
{
  "available": true,
  "enabled": true,
  "codeLogin": true,
  "passwordLogin": true,
  "adminsConfigured": true
}
```

Если панель отключена или `ADMIN_IDS` пуст, `available=false`, а React
показывает «🔒 Админ-панель недоступна» вместо формы входа.

### 10.4. Что умеет админка

- обзор: игроки, суммарный баланс, онлайн, комнаты, заявки;
- поиск игроков;
- ручное начисление/списание баланса;
- подтверждение/отклонение донатов и выводов;
- история операций;
- реквизиты для донатов;
- рассылка сообщения на сайт;
- закрытие комнаты (играющим возвращаются ставки).

## 11. Безопасность и ограничения

- **Сервер авторитетен.** Клиент не присылает карты, очки, баланс или результат.
- **Ставки списываются до игры**, при ошибке возвращаются.
- **`crypto.randomInt`** для карт, кубиков и кодов — не `Math.random`.
- **Rate limit**:
  - HTTP: вход 12/мин, донаты 10/час, админ-вход 8/мин;
  - Socket: `join` 20/10 с, действия 60/10 с, adminLogin 5/мин.
- **Токены**: 32 случайных байта (64 hex), сравнение пароля — `timingSafeEqual`.
- **Гости** могут играть локально, но денежные операции требуют сессию.
- **Чужие карты** не уходят клиенту: `toJSONFor()` скрывает руку и очки других
  игроков до конца партии.
- **XSS/клики** — React экранирует данные; имена очищаются `sanitizeName`.
- **Helmet + CORS + compression** подключены на уровне Express.

## 13. Диагностика

| Симптом | Причина / решение |
|---|---|
| `Сайт ещё не собран` (503) | Нет `webapp/dist` → `cd casino/webapp && npm install && npm run build` или перезапустить `python bot/main.py` |
| `Node.js не найден` | Установить Node.js 18+ или указать `PATH` |
| `Telegram отклонил BOT_TOKEN (401)` | Токен отозван → новый у `@BotFather` в `.env` |
| `Админ-панель недоступна` | Пустой `ADMIN_IDS` или `ADMIN_PANEL_ENABLED=0` |
| `Код не найден` | Код истёк (15 мин) или введён код другого типа → получить новый `/site` или `/admin` |
| `Порт 3000 занят` | Остановить старый процесс или задать другой `PORT` |
| Docker: `cannot connect to the Docker daemon` | Запустить Docker Desktop |
| Комнаты пропали после рестарта | Проверить, что бот и сайт используют один `DB_PATH` |

Полезные проверки:

```bash
curl http://localhost:3000/health
curl http://localhost:3000/api/admin/status
curl http://localhost:3000/api/stats
```

## 15. Как добавить новую игру

1. Добавить тип в `GAME_TYPES` (`casino/server.js`).
2. Написать `init<Game>()` — раздать состояние игрокам.
3. Написать `handle<Game>Action()` — проверить и применить ход.
4. Добавить финал: определить победителей и вызвать `settleRoom(room, ids, "Название")`.
5. В `playerAction` добавить ветку выбора обработчика.
6. В `botTurn` — простую стратегию для ботов.
7. Во фронтенде (`casino/webapp/src/pages/GamePage.jsx`) добавить отображение
   и кнопки действий.
8. Добавить проверки в `tests/web_e2e.js`.

Карты, ставки, выплаты, сохранение и переподключение уже работают автоматически —
новая игра использует те же `Room`, `reserveBets`, `settleRoom` и `saveRoom`.
